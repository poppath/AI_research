# Prompt Library — 16 ชุดคำสั่งสำหรับงาน Meta Ads × AI (ภาษาไทย)

> **Review 7 พ.ย. 2026:** เอกสารเดิมเป็น research snapshot มีตัวเลข/heuristic และข้ออ้างที่ยังต้องตรวจรายกรณี ไม่ใช่กฎสากลหรือ rate ปัจจุบัน; ก่อนใช้ให้ดู [ข้อจำกัดและรายการแก้ไข](../../../REPO-REVIEW-2026-11-07.md) และ `AGENTS.md` โดยเฉพาะก่อนตัดสินใจงบ กฎหมาย หรือ automation.

> วิธีใช้: copy prompt → เติมข้อมูลใน `{...}` → ให้ AI ตอบตาม schema → **ตรวจด้วยคนก่อนใช้ทุกครั้ง**
> กติกา: 1 prompt = 1 งาน · ให้ข้อมูลจริงเสมอ · ห้ามให้ AI คิดตัวเลข performance เอง

## P01 · สกัด Insight จากรีวิว/คอมเมนต์/แชท

```
บทบาท: คุณเป็นนักวิจัยลูกค้า (customer researcher) ที่เชี่ยวชาญตลาดไทย

ข้อมูลนำเข้า:
- กลุ่มสินค้า: {เช่น ครีมบำรุงผิวสำหรับผู้ชาย}
- กลุ่มเป้าหมาย: {เช่น ผู้ชาย 25-40 ในกรุงเทพฯ}
- ข้อมูลดิบ (รีวิว/คอมเมนต์/แชท): {วางข้อความ 50-300 รายการ}

งาน:
1. จัดกลุ่ม pain point (ไม่เกิน 7 กลุ่ม) พร้อมความถี่โดยประมาณ
2. จัดกลุ่ม "สิ่งที่ทำให้ตัดสินใจซื้อ" (buying trigger)
3. จัดกลุ่ม "ข้อกังวล/เหตุผลที่ไม่ซื้อ" (objection)
4. ดึง "ภาษาที่ลูกค้าใช้จริง" อย่างน้อย 15 ประโยค (คำต่อคำ ห้ามแต่งใหม่)
5. ระบุช่องว่าง: สิ่งที่ลูกค้าพูดแต่แบรนด์ยังไม่พูดถึง

รูปแบบผลลัพธ์:
| กลุ่ม | สรุป | ความถี่ | ตัวอย่างคำพูด |
...

ข้อห้าม: ห้ามแต่งคำพูดขึ้นใหม่, ห้ามสรุปเกินข้อมูล, ถ้าข้อมูลไม่พอให้บอกว่าไม่พอ
```

## P02 · ถอดโฆษณาคู่แข่ง (Meta Ad Library)

```
บทบาท: คุณเป็น creative strategist

ข้อมูลนำเข้า:
- คู่แข่ง: {ชื่อ/ลิงก์}
- ตัวอย่างโฆษณาที่เก็บมา: {วางข้อความ/คำอธิบายภาพ/หมายเหตุ}
- สินค้าของเรา: {อธิบาย 3 บรรทัด}

งาน:
1. ระบุ "angle" ของแต่ละโฆษณา (ประโยชน์ตรง/ลบความกลัว/social proof/ราคา/สถานะ)
2. ระบุ persona ที่โฆษณานั้นพูดกับ
3. ระบุ hook pattern ที่ใช้
4. ระบุช่องว่าง: angle ที่คู่แข่งยังไม่ใช้ และเหมาะกับเรา
5. เสนอ 5 concept ที่ "ต่างจากคู่แข่งอย่างมีนัยสำคัญ" พร้อมเหตุผล

ข้อห้าม: ห้ามลอกข้อความ, ห้ามเดาตัวเลขผลลัพธ์ของคู่แข่ง
```

## P03 · สร้าง Persona + JTBD

```
บทบาท: นักกลยุทธ์การตลาด

ข้อมูล: {insight จาก P01} + {ข้อมูลสินค้า} + {ราคา} + {ตลาด}

สร้าง 3 persona ที่ "แรงจูงใจต่างกันจริง" (ไม่ใช่แค่ อายุ/เพศ ต่าง)
แต่ละ persona ต้องมี:
1. ชื่อเล่น + ภาพรวม 2 ประโยค
2. JTBD: "เมื่อฉัน___ ฉันต้องการ___ เพื่อ___"
3. อะไรทำให้ซื้อ (3 ข้อ)
4. อะไรทำให้ไม่ซื้อ (3 ข้อ)
5. ประโยคที่ทำให้เขาหยุดดู (hook)
6. หลักฐานที่เขาต้องการเห็นก่อนซื้อ
7. ฟอร์แมต/placement ที่เหมาะ

ห้าม: ห้ามใช้ stereotype ที่ไม่มีข้อมูลรองรับ, ระบุระดับความมั่นใจของแต่ละข้อ (สูง/กลาง/ต่ำ)
```

## P04 · แผนที่ Offer & Objection

```
ข้อมูล: {สินค้า} {ราคา} {โปร} {objection จาก P01}

งาน:
1. ตาราง objection → หลักฐานที่ต้องใช้ → ครีเอทีฟที่ตอบ objection นั้น
2. เสนอ 3 ระดับ offer (entry / core / premium) พร้อมเหตุผลเชิงจิตวิทยา
3. ระบุ "สิ่งที่ห้ามสัญญา" เพราะผิดกฎหมายหรือเกินจริง

รูปแบบ: ตาราง 3 คอลัมน์ + คำเตือน compliance
```

## P05 · สร้าง Hook 30 แบบ (7 ตระกูล)

```
ข้อมูล: {persona} {awareness level} {angle} {สินค้า}

สร้าง hook 30 ประโยค กระจาย 7 ตระกูล:
ปัญหา / คำเตือน / คำถาม / ตัวเลข / ก่อน-หลัง / POV-เรื่องเล่า / ตรงข้ามความเชื่อ

เงื่อนไข:
- ภาษาไทยธรรมชาติ ไม่แปลตรง
- ≤ 8 คำ สำหรับข้อความบนจอ
- ห้าม clickbait ที่ไม่ได้สัญญาอะไรกับเนื้อหา
- ระบุตระกูล + persona + awareness level ของแต่ละ hook

รูปแบบ: ตาราง | # | hook | ตระกูล | ใช้กับ | เหตุผลที่ควรทำงาน |
จากนั้นเลือก top 5 พร้อมอธิบายว่าทำไม
```

## P06 · สคริปต์ Reels 15 วินาที

```
ข้อมูล: {hook ที่เลือก} {สินค้า} {หลักฐาน} {offer} {CTA}

เขียนสคริปต์ 15 วินาที แบ่งเป็น:
0-2 วิ (HOOK) / 2-5 (PROBLEM) / 5-10 (PROOF) / 10-13 (OFFER) / 13-15 (CTA)

แต่ละช่วงระบุ:
- ภาพ (สิ่งที่กล้องเห็น)
- ข้อความบนจอ (≤ 8 คำ)
- เสียง/บทพูด (≤ 2 ประโยค)

เงื่อนไข:
- ข้อความสำคัญต้องอยู่ใน safe zone (บน 14% / ล่าง 35% / ข้าง 6%)
- ทำงานได้ทั้ง sound-on/off
- ไม่ใช้ intro โลโก้
- ระบุ subtitle ที่ต้องฝัง
```

## P07 · Concept ภาพนิ่ง 10 แบบ

```
ข้อมูล: {persona} {angle} {สินค้า} {ข้อจำกัดแบรนด์: สี/โทน/สิ่งที่ห้าม}

เสนอ 10 concept ภาพนิ่ง (4:5 สำหรับ Feed, 9:16 สำหรับ Stories)
แต่ละ concept:
1. ภาพรวมภาพ (1 ประโยค)
2. องค์ประกอบ: subject / background / props / text overlay (ระบุตำแหน่งใน safe zone)
3. เหตุผลเชิงกลยุทธ์ว่าทำไมภาพนี้หยุดคนได้
4. prompt สำหรับ image generator (ภาษาอังกฤษ)
5. สิ่งที่ต้องระวัง (เช่น ข้อความไทยต้องใส่ทีหลัง)

ห้าม: ห้ามให้ AI สร้างข้อความไทยในภาพ (ให้ใส่ทีหลังด้วย editor)
```

## P08 · Copy 3 ความยาว (Feed / Reels / Threads)

```
ข้อมูล: {hook} {offer} {หลักฐาน} {persona}

เขียน copy 3 ชุด:
A) Feed (125 ตัวอักษรแรกต้องมี hook + offer; ทั้งหมด ≤ 300 ตัวอักษร)
B) Reels (≤ 40 ตัวอักษรแรกสำคัญ; ทั้งหมด ≤ 125)
C) Threads (น้ำเสียงเหมือนโพสต์จริง ไม่ขายตรง; 2-3 ประโยค + คำถามชวนคุย)

แต่ละชุดระบุ:
- headline (≤ 55 ตัวอักษร)
- description (≤ 30)
- CTA ที่เหมาะ
- เหตุผลทางจิตวิทยา 1 บรรทัด

ห้าม: ห้ามใช้ superlative ที่ไม่มีหลักฐาน ("ดีที่สุด", "อันดับ 1") เว้นแต่มีหลักฐาน
```

## P09 · Localization ไทย ↔ อังกฤษ (แบบCultural)

```
ข้อมูล: {copy ต้นฉบับ} {ตลาดเป้าหมาย}

แปลและปรับให้เข้ากับวัฒนธรรม ไม่ใช่แปลตรง:
1. เวอร์ชันแปลตรง
2. เวอร์ชันปรับวัฒนธรรม (idiom, ระดับความสุภาพ, humor)
3. ระบุ "คำที่ห้ามแปลตรง" และคำอธิบาย
4. ระบุความเสี่ยง: คำที่อาจไม่สุภาพ/ผิดความหมายในอีกวัฒนธรรม
```

## P10 · ตรวจ QA ครีเอทีฟ + แบรนด์ + Compliance

```
ข้อมูล: {สคริปต์/ข้อความโฆษณา} {ภาพ/คำอธิบายภาพ} {แบรนด์ไกด์} {อุตสาหกรรม}

ตรวจตาม checklist:
□ safe zone (14/35/6)
□ ราคา/โปร ตรงกับหน้าเว็บ
□ ไม่มีข้อความรับรอง/ตัวเลขที่ไม่มีหลักฐาน
□ ไม่มีคำต้องห้ามของอุตสาหกรรม ({อย./กลต./ธปท.})
□ ภาษาไทยถูกต้อง (สะกด/วรรณยุกต์/คำซ้ำ)
□ น้ำเสียงตรงแบรนด์
□ CTA ชัด 1 จุด
□ ไม่มีภาพบุคคล/ลิขสิทธิ์ที่เสี่ยง

ผลลัพธ์: ตาราง | ข้อ | ผ่าน/ไม่ผ่าน | ระดับความเสี่ยง | วิธีแก้ |
สรุป: ผ่าน / ผ่านแบบมีเงื่อนไข / ไม่ผ่าน
```

## P11 · วิเคราะห์ผลรายสัปดาห์

```
บทบาท: นักวิเคราะห์ performance marketing

ข้อมูล: {CSV export ระดับ ad 7-28 วัน} + {เป้าหมาย CPA/ROAS} + {experiment log}

งาน:
1. สรุปภาพรวม: spend, conversions, CPA, ROAS, MER (ถ้ามี revenue)
2. ระบุ ad set ที่เข้า/ออก learning phase
3. จัดอันดับ creative: top 5 / bottom 5 พร้อมสมมติฐานว่าทำไม
4. ระบุสัญญาณ fatigue (frequency, CTR trend)
5. ระบุ placement anomaly
6. เสนอ action 3 ข้อ: scale / hold / kill (ตาม agent-rules.yaml)
7. ระบุ "สิ่งที่ข้อมูลนี้ยังตอบไม่ได้" (สำคัญ)

ข้อห้าม: ห้ามสรุป causal จากข้อมูล observational, ห้ามแนะนำเพิ่มงบเกิน 20% ต่อครั้ง
```

## P12 · วินิจฉัย Creative Fatigue

```
ข้อมูล: {creative_id} {daily metrics 14 วัน: impressions, 3s views, clicks, conversions, frequency}

วินิจฉัย:
1. fatigue จริงหรือเป็นผลจาก seasonality/auction?
2. ระยะที่เริ่มเสื่อม (วันที่)
3. ตัวชี้วัดที่เสื่อมก่อน (hook rate / CTR / CVR)
4. เสนอทางแก้ 3 ระดับ: เปลี่ยน hook / เปลี่ยนหลักฐาน / เปลี่ยน angle
5. ระบุว่าไม่ควรทำอะไร (เช่น อย่าเพิ่งเปลี่ยน audience)
```

## P13 · ออกแบบการทดลอง

```
ข้อมูล: {สมมติฐาน} {ตัวแปรที่อยากทดสอบ} {งบที่มี} {ระยะเวลา}

ออกแบบ:
1. สมมติฐานที่ falsifiable (ถ้า...แล้ว...เพราะ...)
2. ตัวแปรเดียวที่ทดสอบ
3. กลุ่มควบคุม vs กลุ่มทดลอง
4. ขนาดตัวอย่างขั้นต่ำ (อธิบายเหตุผล)
5. ตัวชี้วัดหลัก + ตัวชี้วัดกันชน
6. เกณฑ์ตัดสิน (ชนะ/แพ้/เสมอ) ก่อนเริ่ม
7. ระยะเวลา + งบ
8. ความเสี่ยงที่ทำให้ผลเพี้ยน

รูปแบบ: 1 หน้า พร้อมบันทึกลง experiment_log
```

## P14 · Post-mortem & สกัดบทเรียนเป็น Rules

```
ข้อมูล: {ผลการทดลอง} {สมมติฐานเดิม} {บริบท}

งาน:
1. ผลจริง vs สมมติฐาน
2. คำอธิบายที่เป็นไปได้ 3 อย่าง (พร้อมระดับความมั่นใจ)
3. บทเรียนที่ "ยกไปใช้ซ้ำได้" (generalizable) vs "เฉพาะกรณีนี้"
4. เสนอ rule ใหม่/แก้ rule ใน agent-rules.yaml (ระบุเงื่อนไข + threshold)
5. ระบุว่าต้องทดสอบซ้ำหรือไม่ และอย่างไร

รูปแบบผลลัพธ์: YAML block ที่พร้อม merge
```

## P16 · สคริปต์แชท + Knowledge Base สำหรับ Business AI

```
ข้อมูล: {สินค้า} {ราคา} {FAQ 20 ข้อ} {นโยบายคืนสินค้า} {ขั้นตอนปิดการขาย}

สร้าง:
1. บทเปิดบทสนทนา 3 แบบ (ตามที่มาของแอด)
2. คำถามคัดกรอง 5 ข้อ (qualification)
3. คำตอบ FAQ 20 ข้อ (สั้น กระชับ น้ำเสียงแบรนด์)
4. เงื่อนไขส่งต่อมนุษย์ (เช่น ถามราคาพิเศษ/ complain/ ต้องการใบกำกับ)
5. บทปิดการขาย 2 แบบ (soft / direct)
6. สิ่งที่ห้ามพูด (ห้ามสัญญาเกินจริง, ห้ามเก็บข้อมูลอ่อนไหว)

รูปแบบ: ตาราง intent → response → fallback
```

## ภาคผนวก: กติกาการใช้ Prompt กับงานโฆษณา

1. **ห้ามให้ AI คิดตัวเลข performance** — ให้คำนวณจากข้อมูลจริงเท่านั้น
2. **ทุก output ต้องมี "ระดับความมั่นใจ"** — ถ้า AI ไม่รู้ ให้บอกว่าไม่รู้
3. **แยกข้อเท็จจริง / สมมติฐาน / ความคิดเห็น** ใน output เสมอ
4. **ภาษาไทย**: ให้ AI ตรวจคำซ้ำและวรรณยุกต์ทุกครั้ง (LLM พลาดบ่อย)
5. **ข้อความที่กระทบกฎหมาย** ต้องผ่านคน + ถ้าจำเป็นผ่าน legal
6. **เก็บ prompt ที่ใช้จริง** ไว้ในโปรเจกต์ เพื่อ reproducibility
